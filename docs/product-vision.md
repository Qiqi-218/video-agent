# 产品愿景：可对话的视频剪辑助手

P1 已经解决“可靠地按时间线出片”。产品下一步是让用户直接对助手说想要的成片，再由助手理解素材、提出有依据的方案、执行剪辑，并继续接受局部修改。

```text
用户：剪成一个热血的比赛逆转集锦，最后保留庆祝镜头
                         ↓
对话助手：澄清目标、展示依据、规划与调用受限工具
                         ↓
多维视频理解：语音、人物、动作/事件、画面、情绪线索、节奏、上下文
                         ↓
可审阅工作流：分析 → 候选 → 时间线 → 预览 → 修改 → 导出
                         ↓
P1 编辑与渲染内核：版本、锁定、来源、验证 MP4
```

## 对话不是一句话“自动剪完”

用户可以说“开头更快一点”“保留主持人这句”“把最激动的三次进球拼在一起”“不要出现某位嘉宾”。助手需要先读取工程和证据，再给出带来源时间的候选与时间线；每次改动走 revision，用户能锁定片段、查看依据、恢复版本和重试导出。

当需求不够明确、素材没有对应内容或判断没有足够依据时，助手应提问或返回 `no_match`，不能把推测当事实。它负责提出和执行受约束的编辑操作，成片是否成功仍以真实渲染与解码验证为准。

## 多维长视频理解

首版不追求“理解一切”，而是让不同证据维度共同服务于选段与解释：

| 维度 | 可提取的证据 | 对剪辑的作用 |
| --- | --- | --- |
| 语音与文本 | 字幕、说话人、关键词、话题、停顿 | 找某段话、删除冗余口播、保留关键表达 |
| 人物与关系 | 人脸/人物出现、主持人/嘉宾/选手标记 | 控制谁出现、做人物线索或反应镜头 |
| 动作与事件 | 进球、冲刺、庆祝、鼓掌、笑声、关键转折 | 找高光、建立事件顺序 |
| 画面与镜头 | 场景、镜头变化、特写/全景、字幕牌、画面质量 | 开场/转场/收尾候选，减少重复画面 |
| 情绪与氛围 | 声音强度、语速、欢呼、表情和画面线索 | 估计紧张、欢快、平静等剪辑节奏线索 |
| 叙事与时间 | 比赛阶段、节目环节、因果/前后关系 | 保证“铺垫—转折—结果”不被剪乱 |
| 节奏与音频 | 节拍、能量、停顿、BGM 段落 | 决定片段长度、切点和音乐衔接 |

情绪是基于可见/可听线索的建议，不是对人物内心的断言。每个判断应保存来源片段、模型/规则版本和理由，允许用户纠正；高风险人物属性不作为首版剪辑条件。

## 可观察的工作流，逐步接近 ComfyUI

目标不是先复刻 ComfyUI 的全部画布，而是把每步分析、参数、输入输出和缓存呈现出来。固定工作流可先以可查看、可调整参数、可重跑的步骤列表展示；节点图和拖拽连线在工具和数据契约稳定后扩展。

首批节点包括：`导入素材`、`提取字幕`、`场景/代表帧`、`事件/情绪线索`、`检索候选`、`规划时间线`、`用户确认`、`渲染预览`、`导出与验证`。节点输出都必须可查看、可追溯、可缓存；时间线写入仍只通过 P1 的版本提交边界。

## 演示场景

比赛首版优先准备两类演示。

1. 综艺片段：根据“剪成 45 秒欢乐反应合集，保留嘉宾的反转台词，结尾用全场笑声”检索台词、人物反应、笑声与镜头，展示对话修改。
2. 体育比赛：根据“剪成 60 秒逆转高光，先铺垫落后，再放关键得分和庆祝”检索比分/解说、动作事件、欢呼和庆祝镜头，展示节奏与叙事。

演示素材必须是自有、已授权、公开可使用或比赛允许使用的内容；公开综艺和赛事片段不能默认用于公开发布。素材清单、权利状态、标注和预期镜头由协作任务 F01 固定。

## 当前边界

P1 已能接收结构化时间线并可靠导出。对话、ASR、事件/情绪分析、工作流界面和多维检索尚未实现；它们是 P2–P4 的主线。完整拆分见 [两人协作计划](collaboration/README.md)。
